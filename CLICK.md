# Синхронизация с @clickuz

Помощник сам открывает отчёт «Платежи» в @clickuz, скачивает файл Excel за каждый месяц от выбранной даты до сегодня, сохраняет все платежи в отдельный журнал и присылает вам в бота платежи, которые ещё не записаны. Записывается только то, что вы разобрали кнопками: бот ничего не вносит в учёт сам и не меняет суммы.

## Как это устроено

```
@clickuz ──(ваш Telegram, только чтение отчётов)──► помощник clicksync (Raspberry Pi)
                                                      │  журнал платежей, периоды, вопросы (PostgreSQL)
                                                      ▼
                         ваш финансовый бот ◄── уведомления и кнопки /click
```

- **Помощник** (`clicksync`, отдельный контейнер) входит в Telegram под вашим аккаунтом. Он отправляет @clickuz только команду `/reports` и нажимает только «💸 Платежи», «▶️» (страницы недельного отчёта), «⬇️ Скачать» и кнопки месяцев вида `2026.11`. Кнопки оплаты, переводов и ссылки нажать невозможно: адаптер их отклоняет.
- **Как читаются отчёты.** `/reports` → «💸 Платежи» показывает платежи за последнюю неделю по 5 на странице, со знаком ➕/➖. «⬇️ Скачать» → месяц → через несколько минут приходит `click-payments-…-ГГГГММ.xlsx` за весь месяц. Период синхронизации — календарный месяц, платежи берутся из файла. Click предлагает примерно год назад, более ранних месяцев нет.
- **Знак и валюта.** В файле нет знака суммы (зарплата и такси выглядят одинаково) и нет валюты. Помощник берёт их из недельного отчёта для тех же платежей (карта, минута, сумма, продавец). У более старых платежей знак неизвестен: при разборе бот спросит «➖ Расход / ➕ Доход». Если в недельном отчёте нет ни одного платежа, валюта берётся из `CLICK_CURRENCY`.
- **Журнал** (`source_transactions`) хранит каждый платёж так, как его показал Click: сумму без пересчёта, валюту, направление, статус, описание, комиссию, маскированный номер карты и время в том виде, как оно напечатано. Каждое изменение (например, «в обработке» → «успешно») записывается в историю изменений.
- **Периоды** (`sync_periods`) помечаются как готовые, неполные или с ошибкой. Неполный период и период с ошибкой будут прочитаны снова, их никогда не пропустит.
- **Учёт** — ваши обычные операции. Платёж попадает туда только после вашего выбора в /click.

## Что проверено, а что нет

Посмотрено вживую (17.11.2026, через `clicksync.inspect`): кнопки `/reports`, «Платежи», страницы недели, «Скачать», список месяцев и разметка файла (столбцы `№ платежа | Сумма | Время | Карта | Сервис | Комиссия | Параметры оплаты | Статус платежа`, суммы без знака).

Проверено тестами (без реального Telegram, сценарий повторяет настоящий бот):
- разбор недельного отчёта (`🗓 Платежи c … до …`, `➖ 37'000 UZS`, `🔹`, `💳`, `🕘`, `✅`/`❌`) и файла `.xlsx` с той же разметкой;
- защита от дублей, повторная обработка тех же и перекрывающихся отчётов, смена статусов, возвраты;
- переход по месяцам до даты начала, конец истории (месяца нет в списке), файл не пришёл, непрочитанные строки;
- знак из недельного отчёта, «неизвестно» для старых платежей и выбор направления при разборе без дублей;
- восстановление после перезапуска и ошибок связи; безопасный повтор записи в учёт;
- сверка баланса (комиссии не вычитаются дважды, переводы между своими картами не считаются доходом или расходом);
- кнопки /click и экспорт.

**Не проверено вживую.** Полный автоматический прогон (все месяцы подряд) ещё не запускался. Возможные сюрпризы:
- файл за месяц Click готовит несколько минут (ждём до `CLICK_FILE_TIMEOUT`, 10 минут), поэтому первая загрузка за год может занять около часа;
- в отчётах Click нет начального и конечного баланса, поэтому сверка баланса честно сообщит «выполнить нельзя»; сравнение журнала с учётом работает.

Считайте синхронизацию рабочей после шага 7, когда первые месяцы загрузятся без ошибок.

## Установка на Raspberry Pi

### 1. Обновите бота

```bash
cd ~/Finance-telegram-bot && git pull
```

### 2. Получите ключи Telegram API

1. Откройте https://my.telegram.org и войдите по номеру телефона.
2. «API development tools» → заполните название (любое, например `finance-sync`) → «Create application».
3. Запомните **api_id** (число) и **api_hash**. Это секрет: не отправляйте их никому, в том числе в чат.

### 3. Впишите настройки

```bash
nano src/.env
```

Добавьте или исправьте строки (они есть в `src/.env.example`):

```
FEATURE_CLICK_SYNC=1
TG_API_ID=ваш_api_id
TG_API_HASH=ваш_api_hash
CLICK_TIMEZONE=Asia/Tashkent
CLICK_CURRENCY=UZS
```

`CLICK_TIMEZONE` — часовой пояс, в котором Click печатает время. Если оставить пустым, помощник не запустится: время не угадывается.

Сохраните (Ctrl+O, Enter, Ctrl+X) и пересоберите бота (в образ добавится библиотека Telethon, в базе появятся новые таблицы):

```bash
./start.sh
```

### 4. Войдите в Telegram (один раз)

```bash
docker compose --profile click run --rm clicksync python -m clicksync.login
```

Введите номер телефона, затем код, который придёт в приложение Telegram, и пароль двухэтапной проверки, если он включён. Всё вводится только в этом терминале и уходит прямо в Telegram: никуда не сохраняется и не печатается. Остаётся только файл сессии `secrets/clicksync/telegram.session`. Он не попадает в git, но даёт доступ к вашему Telegram, поэтому не копируйте его никуда.

Если войти под чужим аккаунтом (не `OWNER_ID`), сессия будет сразу удалена.

### 5. Кнопки отчётов (уже настроены)

Подписи кнопок @clickuz уже вписаны по умолчанию, отдельно ничего настраивать не нужно. Если Click когда-нибудь поменяет кнопки, посмотреть их можно так (программа нажимает кнопку, только когда вы введёте её номер и подтвердите, а кнопки оплаты и переводов не нажимает вовсе):

```bash
docker compose --profile click run --rm clicksync python -m clicksync.inspect
```

Новые подписи вписываются в `src/.env`: `CLICK_BTN_PAYMENTS`, `CLICK_BTN_NEXT_PAGE`, `CLICK_BTN_DOWNLOAD`.

### 6. Запустите помощника

```bash
docker compose --profile click up -d clicksync
docker compose logs -f clicksync
```

В логе должно появиться `Click sync worker started`. Дальше `./start.sh` запускает помощника сам.

### 7. Первая синхронизация

В боте: `/click` → «📅 Дата начала» → введите дату, например `01.10.2026` → «🔄 Синхронизировать сейчас».

Помощник скачает файлы за месяцы от текущего до месяца этой даты. На каждый месяц уходит несколько минут, пока Click готовит файл. В конце бот пришлёт «Из Click загружено новых платежей: N». Дальше каждые 3 часа читается только текущий месяц (и прошлый в первые дни месяца).

## Как пользоваться

`/click` показывает статус: дату начала, работает ли помощник, последний полный период, сколько периодов готово, неполных и с ошибкой, последнюю ошибку.

Кнопки:
- **🧾 Разобрать новые** — платежи по одному. Варианты:
  - категория, и платёж записывается с настоящим временем;
  - «✅ … (как в прошлый раз)» для знакомого продавца;
  - «🔗 Уже записано» — связать с вашей записью: показываются записи с той же суммой ±3 дня;
  - «🔁 Перевод между своими» — не доход и не расход;
  - «➖ Расход / ➕ Доход» — для платежа старше недели, у которого в файле нет знака; после выбора появятся категории;
  - «⏭ Не записывать».
- **🔄 Синхронизировать сейчас** — работает и на паузе.
- **⏸ Пауза / ▶️ Продолжить** — автосинхронизация (по умолчанию каждые 3 часа, `CLICK_SYNC_INTERVAL_MIN`).
- **⚖️ Сверка**:
  - баланс за периоды, если Click его показывает;
  - сравнение журнала с учётом;
  - суммы по картам и валютам без переводов между своими счетами.
- **❗ Вопросы** — расхождения. По каждому видно счёт, период, ожидаемое и фактическое значение, разницу, платежи, которые могут её объяснить, и что от вас нужно. Можно связать с записью, вернуть платёж в разбор, добавить операцию обычным сообщением, отметить «✅ Решено» или «🕓 Оставить нерешённым». Об одном и том же вопросе бот напоминает один раз.
- **📤 Экспорт** — весь журнал в CSV (точные суммы, открывается в Excel).

Платежи, которые вы раньше пересылали боту вручную, связываются сами, если совпадают сумма, минута и продавец. Остальные бот покажет вам, а не запишет повторно.

## Дубли и исправления

- Если у платежа есть свой номер в Click, ключом служит он.
- Если номера нет (так у большинства строк), ключ — маскированная карта + время до минуты + сумма + валюта + описание + порядковый номер среди одинаковых строк месяца. Направления в ключе нет: если знак станет известен позже, запись обновится, а не задвоится. Повторное и перекрывающееся чтение даёт те же ключи, поэтому дублей нет.
- Два одинаковых платежа в одну минуту нельзя отличить от повтора строки. Такие помечаются «неоднозначными», и это видно при разборе.
- Статус не входит в ключ, поэтому «в обработке» → «успешно» обновляет запись, а не создаёт новую. Неизвестный статус или знак никогда не затирает известный.
- Прочитанный файл сразу удаляется с диска: платежи уже в журнале, вторая копия выписки не нужна.
- Если уже записанный платёж стал «отменён» или изменил сумму, появится вопрос. Учёт бот не меняет.
- Каждый запуск перечитывает последние `CLICK_OVERLAP_DAYS` дней (по умолчанию 7), чтобы поймать поздние платежи и смену статусов.

## Безопасность

- Ключи API и сессия хранятся только в `src/.env` и `secrets/`, обе папки исключены из git. В логи не пишутся суммы, тексты отчётов и секреты.
- Команды /click и уведомления доступны только `OWNER_ID`.
- Уведомления приходят от вашего финансового бота, помощник от вашего имени ничего не пишет, кроме `/reports` в @clickuz.

## Отключение

```bash
docker compose --profile click stop clicksync
```

Затем в Telegram: «Настройки → Устройства», завершите сеанс помощника. Можно также удалить сессию: `rm -r secrets/clicksync`. Чтобы убрать /click из бота, поставьте `FEATURE_CLICK_SYNC=0` и выполните `./start.sh`.
